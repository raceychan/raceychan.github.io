# Feature: Tutorial/Basics – OAS (OpenAPI Schema) Docs

## Plan

### Technical Analysis
- Current docs structure is autogenerated (`sidebars.ts`) from `docs/`. We have `docs/http/*` pages that already reference OpenAPI/OAS config (`docs/http/config.md`) and endpoint properties (`docs/http/endpoint.md` shows `in_schema: bool`).
- There is no `docs/tutorial/basics/` directory yet. We’ll add a new tutorial-style page under `docs/tutorial/basics/` to introduce OAS (OpenAPI Specification) basics, how Lihil generates it, where to access it, and how to exclude routes/endpoints from the schema.
- We must ensure terminology clarity: OAS = OpenAPI Specification. The request says “openai-schema”, but the codebase uses OAS/OpenAPI. We’ll clarify that context in the doc while focusing on how to control schema generation.

### Proposed Solution
- Add `docs/tutorial/basics/oas.md` covering:
  - What OAS is and how Lihil emits OpenAPI JSON (path configurable via `oas.OAS_PATH`) and docs UI (`oas.DOC_PATH`). Reference `docs/http/config.md`.
  - How to configure OAS via config file or CLI (example already in `docs/http/app.md`).
  - How to skip including a route/endpoint in OAS using `in_schema=False`:
    - Endpoint-level: decorator keyword (e.g., `@router.get(in_schema=False)`).
    - Route-level default: `Route(props=EndpointProps(in_schema=False))` to exclude all endpoints unless overridden.
  - Tagging and grouping via `tags`, with a link to `docs/http/endpoint.md`.
  - Minimal, runnable Python snippets, Python 3.10, PEP 585 style.
- Keep it short, practical, and cross-link to existing HTTP docs for deeper details.
